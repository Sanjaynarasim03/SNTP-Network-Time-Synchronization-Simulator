# Capturing SNTP Traffic on Localhost with Wireshark

This guide demonstrates how to capture, inspect, and analyze real SNTP UDP packets generated by our simulator on your local machine using **Wireshark**.

---

## 1. Prerequisites
- Wireshark installed on your system ([wireshark.org](https://www.wireshark.org/)).
- The SNTP Simulator running (`python3 run.py`).

---

## 2. Step-by-Step Capture Instructions

### Step 1: Open Wireshark and Select Loopback Interface
Because our SNTP client and server communicate locally on IP `127.0.0.1`, traffic does not travel through your Wi-Fi or Ethernet card.
1. Launch Wireshark.
2. In the list of interfaces, double-click:
   - **macOS:** `Loopback: lo0`
   - **Linux:** `Loopback: lo`
   - **Windows:** `Adapter for loopback traffic capture`

### Step 2: Set the Display Filter
In the top Wireshark filter bar, type:
```text
udp.port == 1123
```
or
```text
udp.port == 1123 || ntp
```
Press Enter. Wireshark will now filter and display only the simulator's UDP datagrams.

### Step 3: Trigger Packets from the Dashboard
1. Open the Web Dashboard at `http://127.0.0.1:5000`.
2. Click **"Sync Once"** or **"Start Sync"**.
3. You will immediately see UDP request and response datagrams appear in Wireshark!

---

## 3. Comparing Wireshark Capture with the Simulator

Select a packet in Wireshark and expand the **User Datagram Protocol** and **Data** (or **Network Time Protocol**) tree:

| Wireshark Field | Raw Bytes | Simulator Packet Inspector Tab |
| :--- | :--- | :--- |
| **Payload Length** | 48 bytes | 48 bytes |
| **First Byte (Hex)** | `0x23` (Mode 3, VN 4) | Client Request (VN: 4, Mode: 3) |
| **First Byte (Hex)** | `0x24` (Mode 4, VN 4) | Server Response (VN: 4, Mode: 4) |
| **Stratum** | `0x01` | Stratum 1 (Primary Reference) |
| **Reference ID** | `LOCL` | `LOCL` (Local reference clock) |
| **Timestamps** | 8 bytes each | $T_1, T_2, T_3, T_4$ NTP 64-bit timestamps |

---

## 4. Architectural Comparison: SNTP vs NTP

| Feature | SNTP (RFC 4330) | Full NTP (RFC 5905) |
| :--- | :--- | :--- |
| **Protocol Format** | Same 48-byte UDP packet format | Same 48-byte UDP packet format |
| **Client Model** | Stateless request/response | Stateful peer-to-peer / client-server |
| **Number of Servers** | Single designated server | Multiple peers (typically 3 to 5) |
| **Clock Filter Algorithm** | None (accepts current sample) | Retains min-delay sample from last 8 polls to reject jitter |
| **Clock Selection Algorithm** | None | Marzullo / Intersection algorithm to reject false-tickers |
| **Clock Discipline** | Immediate step adjustment | Continuous Phase-Locked Loop (PLL) slew to prevent backwards time jumps |
| **Complexity** | ~500 lines of code | Thousands of lines of code |
| **Use Cases** | Embedded systems, microcontrollers, mobile devices | Telecoms, data centers, financial high-frequency trading |
